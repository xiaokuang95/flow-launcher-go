# Project state

A port of [Flow Launcher](https://github.com/Flow-Launcher/Flow.Launcher)
(WPF/C#) to Go and [mygo](https://github.com/egoist/mygo), at
`C:/Users/crazy/Downloads/launch`. The reference source is checked out at
`C:/tmp/flow-ref` (commit `c68afbc`, 2026-10-07).

## How to check it

```sh
go build ./... && go vet ./... && go test ./core/ ./plugins/...
CGO_ENABLED=0 GOOS=linux go build ./... && CGO_ENABLED=0 GOOS=darwin go build ./...

# Run a query without a window, to see the results, their scores and the
# plugin that found them.
./launch.exe --query "chrome"
./launch.exe --query "2+2" --run          # run the first result

# Take a picture of the window, using MyGo's own CapturePage rather than a
# screen capture.
./launch.exe --query "chrome" --capture shot.png
```

**The oracle** (`tools/oracle/`): the reference's C# sources are copied into
it unchanged and run with the .NET SDK, so the Go side can be compared
against what the reference really does rather than against a reading of it.
It needs `dotnet` (9.0.318 is installed; add `/c/Program Files/dotnet` to
`PATH`):

```sh
export PATH="$PATH:/c/Program Files/dotnet"
go test ./core/ -run 'TestMatchesTheReference|TestHashesMatchTheReference'
go test ./plugins/calculator/ ./plugins/url/
```

Compared against the reference so far: the StringMatcher over 1058 cases,
the result hashes over 900, the calculator's expressions and .NET decimal
formatting, and the URL validation rules.

## What is done

**core** (37 files)

- Query parsing (`query.go`), fuzzy matching (`matcher.go`, case for case
  with the reference), the result model (`result.go`)
- The plugin interface and its manager (`plugin.go`): concurrent queries,
  scoring from pins, selection counts and plugin priority, sorting and
  truncation
- Persistence: `History.json` (at most 300 entries),
  `UserSelectedRecord.json` (hash31 over UTF-16 code units, as the
  reference folds it), `MultipleTopMostRecord.json`
- i18n: the reference's 26 language files, embedded and parsed on demand
  (`i18n.go` and `core/languages/`); a plugin's own words through
  `PluginTranslator`
- Themes: the colours of 19 of the reference's themes (`themes_data.go`,
  generated by `tools/extractthemes`)
- Icons: Win32 `SHGetFileInfoW` and `GetDIBits`, turned into PNG
  (`icon_windows.go`)
- `.lnk`: the shell's link object through COM
  (`shortcut_com_windows.go`, a thread of its own and raw vtable calls)
- The JSON-RPC host for plugins of other languages (`jsonrpc.go`), for
  executables, Python and Node
- The plugin store: the official manifest (four mirrors, tried in turn),
  version filtering, an offline cache, and unpacking that refuses a path
  outside the plugin's folder (`pluginstore.go`, `unzip.go`)

**12 built-in plugins** (`plugins/`): calculator, program, explorer,
browserbookmark, sys, shell, url, websearch, windowssettings,
processkiller, pluginsmanager, pluginindicator

**Interface**: a frameless window, icons, highlighted titles, subtitles,
a selected row, a preview panel (F1), the menu of a result, the settings
window (seven pages), a tray icon, a global hotkey, a single instance,
starting at login, and game mode

**Size**: 22,527 lines of Go, 191 tests, 14 packages green

## Deliberate differences from the reference

| | reference | here | why |
|---|---|---|---|
| a query of nothing but whitespace | throws `IndexOutOfRangeException` | answers that nothing matched | a bug in the reference |
| Vietnamese | code `vi-vn`, file `vi.xaml`, so it never loads | the language is looked up as well as the tag | a bug in the reference |
| the calculator's `clamp()` | ignores the upper bound | clamps against both | a bug in the reference |
| the calculator's `pow`/`log`/`ln` | the Mages engine's own bugs, worked around by rewriting | the meaning a user expects | same |
| hosts such as `0.0.0.0` and `999.999.999.999` | .NET Uri's own rules | the behaviour .NET was measured to have, oddity included | checked case for case against the oracle |
| the explorer's file search | the Windows Search index over OLE DB | a bounded walk of the user's folders (six levels, 20,000 entries) | the index provider refuses every query until it has been given a catalog and a property set (`DB_E_ERRORSINCOMMAND`); the `FileIndex` interface is there to put it back |
| Firefox bookmarks | reads `places.sqlite` | not read | needs a SQLite driver, and no new dependency was wanted |

## What is not done

- **DialogJump (Alt+G)**: the shell's `Shell.Application` object answered
  `DISP_E_MEMBERNOTFOUND` to every late-bound `Invoke`, whatever the
  locale, the class context or the argument description (all checked
  against the header). The half-finished code was taken out again, and
  `DialogJumpHotkey` in `core/settings.go` says it is not implemented.
- **Checking for a new version**: `CheckForNewUpdate` is an empty hook.
  This launcher has no release channel, so anything written for it could
  not be checked.
- **Installing from the store**: the interfaces are there and a real
  download and unpack was checked (the store's *Power Plans*), but the
  whole "the user installs it and it is there after a restart" path has
  not been walked.

## Traps worth remembering

- **`view()` must call `applyTheme`.** It was dropped once while removing
  debug code and the theme silently stopped working — the picture was
  byte for byte the same as before, which is what gave it away.
- **`ui.Split`'s first argument is the width of the first pane.** Passing
  the preview's width squeezes the results to nothing.
- **`Search` must not merge an already merged batch.** The list a
  `SearchStreaming` callback carries is already merged; merging it again
  duplicates results.
- **`Search` takes the last streamed batch**, not a running total.
- **Enter comes from `ui.TextInput`'s `Submitted()`, not from
  `c.Shortcut(0, ui.KeyEnter)`**, and Shift+Enter arrives there too, told
  apart by `c.Modifiers()`. Ctrl+C and Alt+Up/Down are taken by the text
  input, so they have to be read in `HandleInput`.
- **`PythonRunner` must let `ExecutableRunner.Run` append the request.**
  Appending it in the runner as well loses it, and the plugin is handed an
  empty argument.

## Speed

Typing used to feel slow: a query took about 320 ms, and the first
keystroke after opening the window took half a second. Five things caused
it, and all five are fixed.

- **The explorer walked the user's folders for every keystroke.** The walk
  is now kept for 30 seconds (`walkIndex.entriesNow`), read again when it
  is old or on F5. 320 ms → 6 ms.
- **The walk happened while the user was typing.** Reading the folders
  takes about 400 ms, and it was done by whichever search found the walk
  missing or old — which is the first thing typed after the launcher
  starts, and again every thirty seconds. `walkIndex.Warm`, called from
  the explorer's `Init`, reads the folders as the window comes up, and
  `entriesNow` answers from the walk it has, however old it is, while the
  folders are read again in the background. Only a search with nothing at
  all to answer with waits for a walk. The first keystroke went from
  390 ms to the 30 ms a search costs.
- **Every name was fuzzy-matched.** A cheap in-order subsequence check
  (`isSubsequence`) now rejects a name before the matcher scores it; a
  fuzzy match cannot succeed without it, so the results are the same. The
  program plugin's check looks at every field `resultFor` can match
  (`mightMatch`: the name, the localized name, the executable's name and
  the description), and is left out when the matcher folds accents away,
  because a query may then match a letter a name spells with a diacritic.
- **Icons were read while the window was drawn**, and reading a `.lnk`
  takes about 120 ms because the shell has to resolve the shortcut first
  (a plain `.exe` is 6 ms). `iconCache.bitmap` now reads one in the
  background and asks for a new frame when it is there; a row draws
  without its icon until then.
- **The process killer asked the machine for every process, and a window
  title for each, on every keystroke.** The list is kept for two seconds
  (`Plugin.runningNow`) and dropped when something is ended.

Measured with all twelve plugins loaded, median of seven runs, each query
asked once before it is measured: `c` 32 ms, `ch` 15 ms, `chr` 12 ms,
`chrome` 7 ms, `README` 11 ms, `s` 1 ms, `kill` 1 ms, `b` 0.5 ms. What is
left of `c` is the explorer scoring its 20,000 files (26 ms) and the
program plugin scoring its 8,600 programs (14 ms), which the engine runs
at the same time.

## Known problems

- **The program plugin's defaults are not the reference's.** The reference
  starts with `EnableDescription` false, `HideAppsPath` true and
  `EnablePathSource` false; `plugins/program/program.go`'s
  `DefaultSettings` has them true, false, true. The last one matters most:
  indexing the `PATH` is what turns 200 programs into the 8,600 this
  machine has, and it is most of what a program search costs. The three
  were written that way in the first commit and are not among the
  deliberate differences above. Whether to match the reference, which
  changes what the user sees, has not been decided.
- `go vet` reports four `possible misuse of unsafe.Pointer` in
  `core/com_windows.go`. They are addresses the system handed back, turned
  into pointers again, which Go cannot tell apart from its own; the comment
  there says so. **The subset of vet that `go test` runs does not include
  `unsafeptr`, so the tests are unaffected.**
- `Hotkey` in `Settings.json` may be empty, written by an older build.
  `applyDefaults` fills it in as `Alt + Space` in memory but does not write
  the file back.

## While working on it

- The repository is https://github.com/xiaokuang95/flow-launcher-go. Three
  commits so far: the port itself, the README and licence, and the speed
  work (`app.go`, `plugins/explorer/`, `plugins/program/`,
  `plugins/processkiller/`, `plugins.go` and this file).
- **A test must never really do something to the machine.** Every platform
  action lives behind an injectable field (`sys.Machine`, `shell.Runner`,
  `processkiller.Processes`, `url.Opener`, `program.Finder`,
  `explorer.FileIndex`, `windowssettings.Opener`); `New()` fills in the
  real one and a test fills in a fake and asserts what was asked for.
- A plugin's words come from two places: the launcher's own keys through
  `core.T` (look one up with `go run ./tools/i18nkeys en <pattern>`), and
  the plugin's own through `core.PluginTranslator` over its embedded
  `Languages/*.xaml`.
- To add a plugin, read `docs/plugin-authoring.md`.
